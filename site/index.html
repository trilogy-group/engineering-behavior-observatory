Every finding traced to the native line behind it.

The Engineering Behavior Observatory captures how an engineering agent did the work: native sessions, tool calls, hooks and workspace changes, across eight harnesses. Each behavioral assessment cites the records it rests on, and each published number recomputes from the study's own data.

Signal path

Execution completion, capture quality and task quality are different facts, so EBO keeps them apart. Native evidence stays authoritative: every later stage is derived from it and never replaces it.

  1. Frozen task and harness

    An admitted, digest-pinned task packet or Harbor task, run by one selected native harness. Observational tasks need no reference solution.

  2. Capture

    Native messages, tool activity, exposed lifecycle hooks, usage, OTLP receipt and workspace state, written continuously. Failed and interrupted attempts stay valid partial bundles.

  3. Qualification

    Each bundle's evidence is checked before anything is derived from it. An unqualified bundle is rejected before normalization.

  4. Normalization

    Native records project into one schema of observation categories, not a shared protocol.

  5. Evaluation

    Structural extractors report exact facts. An LLM judge reads an explicit evidence selection, optionally blinded to the evaluated model, weighs an alternative explanation and may abstain.

    constructiveadversemixedcontext-dependent

  6. Claims

    A study's claims are authored, never generated, and validated: each number recomputes, each supporting assessment exists, each cited line re-hashes.

  7. Atlas and packets

    Explore in the Atlas; share an evidence packet that a partner verifies offline against its manifest.

Anatomy of a claim

What a partner receives for each finding. Validation fails if one number no longer recomputes or one cited line no longer hashes to its recorded SHA-256; partner and restricted packets are built only when every claim validates.

Evidence packets

One folder a partner can open from disk: narrative, claims, evaluations, metrics and qualified evidence, cross-referenced, with the interactive viewer when the folder is served over HTTP.

Packet contract

VariantSharedRemoved or withheld
internalEverythingNothing
partnerAll data, under the export pipeline's sharing rulesSecrets, build environment values, local paths and users, hidden reasoning; a string the final scan still flags is withheld whole
restrictedNarrative, claims, evaluations, metrics and the viewerUnit text reduced to structural labels; commands, targets, error text and code removed; native lines, records, audits and tables withheld and listed with their SHA-256
 
ebo packet build <bundle-dir> <output-dir> --variant partner
ebo packet verify <packet-dir>    # or open verify.html

manifest.json (ebo.packet/v1) lists every file with its SHA-256, size, media type, layer and redaction count. ro-crate-metadata.json is an RO-Crate 1.2 description generated from it.

Operating constraints

The rules every adapter, extractor and export is reviewed against.

Native evidence is authoritative
Sessions, streams, events and hooks are semantic evidence; OpenTelemetry is timing and resources; the workspace is the outcome.
Nothing is synthesized
Missing or unsupported evidence is represented explicitly, never turned into false or zero.
Retries never replace
A retry is a new linked attempt; the failed or interrupted one stays a valid partial bundle.
Export fails closed
Unknown sharing classification blocks export. Secrets, environment values, local identifiers and hidden reasoning are excluded.
Judges can abstain
A semantic claim needs cited evidence and an alternative explanation. Human calibration is optional and recorded separately.
Exploratory is labeled
Only EBO's aggregation reports are certified; every other number says what it is.
