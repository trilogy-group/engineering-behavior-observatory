How it works

From a frozen task to a claim you can verify.

Execution completion, capture quality and task quality are different facts. EBO keeps them apart, and native evidence stays authoritative: derived views never replace it.

  1. 01 Capture

    Seven harnesses, one capture path

    Messages, tool activity, exposed lifecycle hooks, usage and workspace outcomes are retained as each harness emits them. Observational tasks need no reference solution or pass/fail verifier.

  2. 02 Ontology

    One schema for every harness

    A Codex commandExecution and a Pi bash call both land as a tool event; an Agent SDK PreCompact hook becomes context · before. Missing evidence stays explicit, never zero.

    • message
    • model-request
    • tool
    • context
    • permission
    • delegation
    • artifact
    • validation
    • runtime
    • outcome

  3. 03 Evaluation

    Judgments grounded in cited lines

    Structural extractors report exact facts. An LLM judge sees an explicit evidence selection, optionally blinded to the evaluated model's identity, must weigh an alternative explanation, and may abstain.

    constructiveadversemixedcontext-dependent

  4. 04 Claims

    Every number recomputes

    A claim carries its numbers and how they are computed, its supporting judgments, and each citation's path, line number and SHA-256. The validator recomputes the numbers and re-hashes every cited line.

  5. 05 Cohorts

    Any experimental design

    Compare matched conditions across models, harnesses or configurations, over repeated trials. Add human review or calibration when the experiment calls for it; it is recorded separately.

  6. 06 Atlas & packets

    Explore, then share what holds

    Browse clusters by arm, swimlanes and assessments in the Atlas. Ship an evidence packet, from narrative to native records, that a partner can verify against its manifest offline.

The Behavior Atlas

From a bar in a lane to the native record.

Each trial is a lane of actions in order: inspect, edit, read, check, shell and version control, with errors, failure chains and compactions marked. Context per request rides underneath. Click any bar to open the record the agent produced, verbatim.

  • Cluster × arm enrichment with observed, expected and adjusted residuals
  • Aligned diffs between trials, and Perfetto trace export
  • Assessments matrix, claims ledger and attempt audits

Numbers computed in the viewer are exploratory; certified tallies come from EBO's aggregation reports.

Get started

A first report in a few minutes, no credentials.

The bundled synthetic demo makes no model calls. It shows evidence drilldown, review states, missing evidence and comparison caveats. Requires Node.js 24.19.0, Git and npm.

Quickstart CLI reference Releases 
# from a source checkout
git clone \
  https://github.com/trilogy-group/engineering-behavior-observatory.git
cd engineering-behavior-observatory
nvm use && npm ci && npm run build && npm link

# explore a synthetic trajectory report
node dist/test/atlas-fixture.js .ebo/first-look
ebo corpus query .ebo/first-look/index.jsonl
ebo atlas build .ebo/first-look/atlas.json .ebo/first-report
# open .ebo/first-report/index.html

Native evidence is authoritative

Sessions, streams, events and hooks are semantic evidence; OpenTelemetry is timing and resources; the workspace is the outcome.

Nothing is synthesized

Missing or unsupported evidence is represented explicitly, never turned into false or zero.

Partial runs are kept

Failed and interrupted attempts stay valid partial bundles. A retry is a new linked attempt, never a replacement.

Export fails closed

Unknown sharing classification blocks export. Secrets, environment values, local identifiers and hidden reasoning are excluded.
